# Contributing

Thank you for contributing to HDCS engineering work.

## Contribution Principles

- Prefer engineering value over visual polish.
- Keep claims evidence-based and reproducible.
- Document assumptions, risks, and limitations.
- Do not claim operational or flight capability without validation evidence.

## Workflow

1. Open an issue describing the engineering problem and expected outcome.
2. Propose changes in a feature branch.
3. Submit a PR using the repository PR template.
4. Ensure documentation and risk statements are updated with technical changes.
5. Address review feedback before merge.

## Minimum PR Requirements

- Clear engineering rationale
- Assumptions and risk notes
- Updated affected documentation
- No secrets in code or docs

## Commit Quality

- Use concise, descriptive commit messages.
- Keep changes scoped and logically grouped.

## Scope Discipline

- Avoid unrelated refactors in the same PR.
- If a change alters interfaces, update boundary documentation and version notes.
