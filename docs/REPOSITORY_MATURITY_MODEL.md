# HDCS Repository Maturity Model

## Level 0 — Idea

Concept only; no validated implementation.

## Level 1 — Prototype

Early implementation with experimental functionality.

## Level 2 — Functional

Core behavior works with basic documentation and reproducibility.

## Level 3 — Engineered

Structured architecture, tests, CI, and operational documentation.

## Level 4 — Production-Ready

Security controls, release discipline, strong reliability and maintainability practices.

## Level 5 — Reference Project

Exceptional public-quality implementation suitable as a reusable standard.

## Labeling Rules

- Every active repository should declare its current maturity level in README.
- Claims must match evidence (tests, CI results, docs, and architecture artifacts).
- Archive or private status should be used when a repository no longer reflects current standards.
